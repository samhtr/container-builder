04 · Networking & persistent storage

Optional runtime settings. Port publishing applies to Docker CLI; storage is generated for the selected deployment format.
Format: [IPv4 address:]host-port:container-port[/tcp or /udp]. Ports must be 1–65535; TCP is the default. Omitting the address publishes on all host interfaces. Avoid host ports already in use.Enable matching services through a profile, settings, or the Console. Publishing a port does not enable its service. Kubernetes exposure requires a separate Service and cluster networking configuration; these mappings are not used there.
Docker creates a named volume if needed. A bind-mount directory must already exist on the Docker host.
The claim must exist in the selected namespace and support the chosen node. This builder does not provision storage.
Mounts storage at /data and sets VOLUME_MOUNT to the same path. Give each Canary its own storage. Durability and node portability depend on your storage provider. A seed provides deterministic identity; a volume persists on-disk data.The generated /run mount uses temporary memory-backed storage. For persistent /data, keep a Docker volume, bind mount, or Kubernetes PVC. Kubernetes emptyDir with medium: Memory loses data when its Pod is removed and uses container memory. Storage lifecycle ↗
